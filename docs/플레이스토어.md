# Google Play 운영 메모

동계부를 Google Play **내부 테스트**로 나눠 주는 데 필요한 것을 모아 둔다. 빌드와 배포 방법은 [배포.md](배포.md#play-배포),
스토어 등록정보와 설문의 답은 [store/README.md](store/README.md)에 있다.

## 한눈에

| 항목 | 값 |
|---|---|
| 배포 방식 | 내부 테스트(테스터 100명까지, 검토 없이 몇 분 안에 나감). 검토를 받으려고 둔 비공개 테스트(Alpha)도 있다 |
| 개발자 계정 | 개인 계정, 표시 이름 '읻옥언'. 신원 인증은 2026-10-08에 끝났다 |
| 앱 | 동계부(`com.dong.budget`). 카테고리 금융, 콘텐츠 등급 전체 이용가(한국 3세 이상), 타깃 13세 이상 |
| 참여 링크(내부 테스트) | https://play.google.com/apps/internaltest/4701184835279310899 |
| 테스터 목록 | 이메일 목록 '나'. 내부 테스트와 비공개 테스트가 같은 목록을 쓴다 |
| 앱 서명 키 | 지금 쓰는 서명 키(SHA-256 `25:69:E8:E1…F8:DD`)를 PEPK 로 Play 에 올렸다. 업로드 키도 같은 키다 |
| 자동 업로드 | 시크릿 `PLAY_SERVICE_ACCOUNT_JSON` + 변수 `PLAY_UPLOAD_ENABLED=true`(2026-10-08에 켬) |
| 나가 있는 버전 | 내부 테스트 1.9.0(22, 2026-10-12 태그 배포로 자동 업로드), 비공개 테스트 1.8.1(21). 첫 검토 통과(2026-10-10) |

## 지금 상황 (2026-10-12)

- **1.9.0 배포**: 검토 통과 뒤 처음으로 태그 배포가 내부 테스트에 자동으로 올렸다(배포 작업 9분, 고정지출 시뮬레이션 포함).
- **첫 검토 통과**: 2026-10-10에 보낸 검토(변경사항 14개)가 같은 날 통과해 게시됐다.
- Play 페이지에 이름 '동계부', 개발자 '읻옥언', 강아지 아이콘, 스크린샷, 등급 3세 이상이 보인다. 내부 테스터에게도 같다.
- 앞으로 업데이트는 내부 테스트로 검토 없이 몇 분 안에 나간다.

## 검토 결과가 오면

- **통과**: 할 일 없음. 앞으로 업데이트는 지금처럼 내부 테스트로 검토 없이 몇 분 안에 나간다.
- **반려**: 사유를 보고 고쳐서 다시 낸다. 반려된 상태에서는 다음 제출(내부 테스트 업데이트 포함)도 검토가 끝나야 나간다.

## 왜 비공개 테스트가 있나

- 내부 테스트는 원래 검토를 안 하는 트랙이다. 내부 테스트에만 버전이 있으면 게시 개요의 '검토를 위해 제출'이
  "대시보드에서 필수 단계를 완료하세요"로 잠겨 있다. 비공개 테스트에 버전을 하나 두자 풀렸다(2026-10-10).
- 비공개 테스트는 1.8.1 에 그대로 둔다. 거기에 새 버전을 올리면 매번 검토를 받는다. 업데이트는 내부 테스트로만 한다.
- 테스터 12명이 14일 동안 써야 한다는 조건은 **프로덕션(누구나 검색해서 받는 정식 출시)을 신청할 때만** 필요하다. 내부·비공개 테스트와는 상관없다.

## 친구를 더할 때

1. Play Console → 테스트 및 출시 → 테스트 → 내부 테스트 → **테스터** 탭 → 목록 '나' 옆 → → 그 친구의 Google 계정 이메일을 넣고 저장한다.
2. 친구에게 위의 참여 링크를 보낸다. 친구가 **테스터 되기**를 누른 뒤 Play 스토어에서 설치한다.
   - 이미 GitHub 에서 받은 동계부가 있으면, Play 쪽 버전이 더 높을 때 **업데이트**로 뜨고 지우지 않고 넘어온다.
     넘어오기 전에 백업 파일을 하나 만들어 두라고 한다.
3. 그 뒤 업데이트는 Play 가 알아서 한다. 앱 홈 맨 위의 새 버전 줄을 눌러 바로 받을 수도 있다.

링크만 보내서는 안 된다. 목록에 이메일이 없는 계정은 참여할 수 없다.

## 업데이트(배포)

- 늘 하던 대로 태그를 하나 올리면 GitHub Releases 에는 APK, Play 내부 테스트에는 AAB 가 올라간다(자세히는 [배포.md](배포.md)).
- Play 쪽 출시 노트는 보내지 않는다. 바뀐 점은 앱의 패치노트에서 본다.
- 스토어 등록정보(이름·설명·스크린샷)를 고치면 그 변경만 검토를 받는다. 자료는 [store/](store/)에 있다.

## 계속 챙길 것

- **해마다 targetSdk 올리기**: 매년 8월 말쯤 기준이 오른다. 못 맞추면 새 버전을 못 올린다(2026년 기준은 API 36, 지금 36).
- **계정 살려 두기**: 180일 안에 한 번은 Play Console 에 들어가고, 연락처(전화·이메일) 인증을 유지한다. 안 쓰는 계정은 닫히고 등록비(25달러)는 돌려받지 못한다.
- **구글의 요청 메일**: 새 선언이나 양식을 내라고 하면 기한 안에 답한다. 안 하면 업데이트가 막힐 수 있다.
- **개인정보처리방침**: 앱이 다루는 정보가 바뀌면 [privacy.md](privacy.md)를 고치고 시행일을 바꾼다.

## 비밀 파일 (`secrets/`, git 에 안 올라감)

| 파일 | 내용 |
|---|---|
| `dong-budget-release.jks` | 서명 키(`keystore.properties` 의 `storeFile`). **잃어버리면 안 된다.** 프로젝트 밖에도 한 벌 백업해 둔다 |
| `dong-budget-deploy-….json` | Play 서비스 계정 키. GitHub 시크릿 `PLAY_SERVICE_ACCOUNT_JSON` 과 같은 내용 |
| `dong-budget-signing-key.zip` | PEPK 로 암호화해 Play 에 올린 서명 키. 다시 쓸 일은 없다 |
